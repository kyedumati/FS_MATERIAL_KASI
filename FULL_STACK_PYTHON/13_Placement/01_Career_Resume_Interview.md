### Placement is a skill — not luck

After 16 weeks of Python full stack, **technical skill alone does not guarantee offer**. Indian hiring involves:

- Resume screening (HR + ATS)
- Aptitude/online tests (many service companies)
- Technical rounds (Python, Django, SQL, React basics)
- HR/manager (communication, salary, notice period)

This module turns you from "course completed" to **hire-ready candidate**.

### Agile/Scrum in 5 minutes (interview vocabulary)

Most Indian product and service teams say they are **Agile**.

| Term | Meaning |
|------|---------|
| **Sprint** | 1–2 week delivery cycle |
| **Standup** | Daily 15-min: yesterday, today, blockers |
| **Backlog** | List of tasks/features prioritized |
| **Scrum Master** | Facilitates process (not your boss necessarily) |
| **Product Owner** | Defines what to build |
| **Retrospective** | End of sprint: what went well/poorly |

**Interview line:** "In training we simulated sprints with weekly demos and Git commits — similar to standup deliverables."

### How to position your background

| Recent graduate | Experience in another field |
|---------|-----------------|
| Emphasize projects, CGPA, internships | Emphasize transferable skills + why tech |
| Stack: Python, Django, React, MySQL | Prior domain + new stack bootcamp projects |
| Expect 3–6 LPA ranges (varies by city) | Honest about previous experience level |

## Concepts

### Resume structure (India Python roles)

1. **Header:** Name, phone, email, LinkedIn, GitHub, city
2. **Summary:** 2 lines — role target + stack + project highlight
3. **Skills:** Python, Django, DRF, React, MySQL, Git, REST, HTML/CSS (honest levels)
4. **Projects:** 2–3 with bullet impact (built X, used Y, result Z)
5. **Education:** Degree, year, college (reverse chronological)
6. **Certifications / Training:** KSR Python Full Stack — dates
7. **Optional:** Switcher — previous role 1–2 lines max

**Avoid:** Photo unless employer asks, full address, hobbies essay, lie about experience.

### STAR method (projects and prior work)

**S**ituation — context  
**T**ask — your responsibility  
**A**ction — what you did  
**R**esult — measurable outcome  

**Example (BPO → Developer):**  
S: Handled 50+ customer tickets daily in telecom process.  
T: Team wanted automated FAQ responses.  
A: Learned Python, built Flask FAQ API prototype in training capstone.  
R: Reduced lookup time in demo scenario; motivated completing the KSR full-stack course.

**Try these (2 programs):**

**Program 1 — STAR for Task Manager**

```markdown
Situation: Tasks were visible to every user in class demo
Task: Make tasks private per owner
Action: Added User FK, @login_required, filtered QuerySet
Result: User A cannot see User B tasks; demo passed checklist
```

**Program 2 — STAR for Git hygiene**

```markdown
Situation: .env with DB password almost pushed
Task: Stop secret leaks
Action: Added .gitignore, rotated password, wrote .env.example
Result: Repo clean; checklist green for deploy lab
```

## Practice Exercises

### Basic

1. Draft resume v1 — peer review swap in pairs.
   **Model answer:**
   One page: contact, 3–5 bullet projects with tech + outcome, skills matching JD keywords, education. Peer checklist: quantify results, remove fluff, fix typos, ensure GitHub/LinkedIn links work.

2. Update LinkedIn headline and add 5 skills.
   **Model answer:**
   Headline example: `Python Full Stack Developer | Django · React · MySQL`. Add skills such as Python, Django, MySQL, JavaScript/React, Git — mirror your resume and pin them.

3. Write 90-sec intro script and read aloud 3 times.
   **Model answer:**
   Structure: who you are → training focus (Python full stack) → one project result → what role you want. Keep under 90 seconds; practice aloud until smooth, not memorized-robotic.

### Intermediate

1. Two STAR stories documented (1 technical challenge, 1 teamwork).
   **Model answer:**
   Technical: Situation (CORS failing in React+DRF) → Task (ship demo) → Action (fixed headers, documented) → Result (demo worked). Teamwork: conflict on Git merge → coordinated branches/PR review → on-time delivery.

2. Pin 2 GitHub repos; add README screenshot each.
   **Model answer:**
   Pin capstone + one strong lab. Each README needs title, setup, screenshot of running UI, and tech stack. Profile → Customize pins → select the two repos.

3. Apply to 5 suitable roles with customized summary line.
   **Model answer:**
   For each JD, rewrite the resume summary to echo 2–3 required skills (e.g. Django REST, React). Track company, role, date, and summary line used in a simple spreadsheet.

### Interview-style

1. Answer: "Difference between Django and Flask?" in 45 sec.
   **Model answer:**
   Django is batteries-included (ORM, admin, auth) for larger apps; Flask is a lightweight microframework where you add extensions as needed. I use Django for full portals and Flask for small APIs/prototypes.

2. Walk through your capstone architecture on whiteboard.
   **Model answer:**
   Sketch: React/Django templates (UI) → Django/DRF views → ORM/MySQL → auth/sessions. Mention env config, one key endpoint, and how you deploy (e.g. Render). Keep boxes and arrows, not code.

3. "Why should we hire you for this role?" — your answer.
   **Model answer:**
   Tie your projects to their stack, show you learn fast (cite a bug you fixed), and state you can contribute from week one on CRUD/APIs while growing into their domain. End with enthusiasm for their product, not generic praise.

## Interview & Discussion Q&A

### Discuss in class

1. Is one perfect project better than five half-done repos?
2. How to answer "expected CTC" as an entry-level candidate in Hyderabad vs Tier-2 city?
3. prior experience in another fields: how to handle "why leave previous field?"
4. What is imposter syndrome and normal response?
5. Referrals — how to ask politely without being pushy?

*No memorized script — push for plain-English answers, then continue to interview Qs below.*

### Interview answers

**Q1. Tell me about yourself.**  
**A:** Structured 90-sec: background, training/stack, flagship project, role goal.

**Q2. Walk me through your best project.**  
**A:** Problem, architecture (React + DRF + MySQL), your contributions, challenge solved, link.

**Q3. What is Agile?**  
**A:** Iterative delivery in sprints with continuous feedback, standups, backlog prioritization.

**Q4. Django ORM advantage?**  
**A:** Database operations in Python, migrations, less raw SQL for common CRUD — faster development.

**Q5. Why Python full-stack development?**  
**A:** Honest motivation, structured training completed, portfolio proof, long-term commitment — tie past skills (communication/analytics) as assets.
